## Operator acceptance: two distinct experiments

### A. Scientific judgment on existing frozen historical tasks (first)

Use [the original comparison plan](../audit/agent_comparison/PLAN.md) and its
existing rubric, manifests and answer format unchanged. Start with CAL-1/CAL-2,
then T1/T2/T3 if the environment is sound. Verify the frozen local bundles
using the existing build_tasks.py --verify entry; missing private bundles or
actual installed Skill/CLI/MCP must be reported rather than reconstructed
from answer keys. The original A vs B comparison changes only the
PD-RW-Agent component; the B1/B2 sub-axis remains optional. Config C is still
read-only feasibility in that frozen protocol, not a real AIDE run.

Use separate clean sessions with the same model/version, strategy brief,
input window and budgets. Give each solver only the permitted task bundle
and its appropriate installed component; do not mount the repository checkout,
answer keys, other arms' outputs, later project records or CASE_LIBRARY.
The public answer keys can be memorized or recovered; offline isolation and
fresh prospective held-out tasks are needed for stronger independent evidence.
If a solver accesses the keys or a forbidden source, flag the affected arm
invalid instead of scoring it as a scientific failure. Retain missing metrics
as UNKNOWN. Blind the arm labels before scoring with the existing rubric.
The host must establish actual permissions; this document authorizes nothing.

### B. Specialist algorithm-search acceptance (separate new experiment)

Orchestrator's [fixed public grouped synthetic AIDE pilot](https://github.com/phr-devil/PD-RW-Orchestrator/blob/b4e93225142e49b7647cdc23cfb2074b47616074/docs/SPECIALIST_INTEGRATION.md)
now provides deterministic inputs and independent RMSE scoring. This is a
small interface/engineering test, not the frozen historical T2 or a
publication-quality benchmark.

After the required operator authorization and isolation, compare fresh
independent roots generated by that pilot for:

- general-purpose host using PD-RW rules;
- the same host with PD-RW-Agent;
- the pinned AIDE specialist through Orchestrator.

Keep legal features, group split, input bytes, test rows and the external
evaluator identical. Match models and budgets where possible; record
differences and actual cost/turns/wall time rather than pooling unlike arms
as a component-only effect. Only supply worker/data and task.md plus the
minimal installed host components; exclude reviewer source, truth generator,
answer keys, private project data and other runs. No protected source access
or external model use without original authorization.

The solver should produce candidate code and predictions. The trusted
operator must independently inspect and replay the selected code on the
frozen inputs before exporting its predictions. The scoring interface
measures provided predictions, not provenance or scientific validity; retain
the exact code/prediction hashes, execution evidence and independent audit.
Use the same scorer for all arms, report linear and mean baselines and
per-group errors, and distinguish no-run, invalid, and valid measured
outcomes. Do not infer paper potential, scientific superiority or overall
agent effectiveness from this synthetic fixture. After this engineering
gate, design a real prospective research comparison under original scope.

Do not implement a second synthetic data generator or evaluator here.
Use the existing Orchestrator tool; keep the general-host route independent
for actual research. Neither experiment was executed by this documentation
change.
